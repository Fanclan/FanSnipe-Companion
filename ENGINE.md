# StreamSnipe local engine

Requires Node.js 24 or later with `node:sqlite`, plus `yt-dlp`, `ffmpeg` and `ffprobe` on PATH (or supplied paths). Install with `npm ci`, run `npm test` and `npm run build`, then `npm start`. No media is sent to a hosted StreamSnipe service. S3 uploads are initiated explicitly and go directly to the configured user-owned endpoint.

`createEngine(options)` from `dist/app.js` returns `{app, server, auth, local, start, stop}`. `start()` resolves to Node's `AddressInfo`; `stop()` finalizes active jobs. Options: required `dataDir`; optional `recordingsPath`, `dashboardPath`, `host`, `port`, `ytDlpPath`, `ffmpegPath`, `ffprobePath`, `mode` (`desktop` or `docker`), `allowedOrigins` (exact origins), `setupToken`, `monitor` (false disables automatic checking), `fixtureOrigins` (exact origin allowlist for tests only). Native integrators call `auth.listPending()`, `auth.approve(id)`, `local.setRecordingsPath(absolutePath)`, `local.diagnostics()`, and `local.importLegacy(absoluteDatabasePath)`. Import opens the original database read-only, disables imported channels, and references existing media without moving or deleting it. Import is idempotent for the same legacy IDs. It imports recognized supported platforms; unsupported legacy URLs are skipped. Preserve a backup before migration.

The standalone server maps `DATA_DIR`, `RECORDINGS_PATH`, `DASHBOARD_PATH`, `HOST`, `PORT`, `STREAMSNIPE_MODE`, comma-separated `ALLOWED_ORIGINS`, `SETUP_TOKEN`, `YT_DLP_PATH`, `FFMPEG_PATH`, and `FFPROBE_PATH`. Defaults are loopback port 47821 and desktop mode. Docker mode creates a random persistent setup token in `DATA_DIR/setup-token`, mode 0600, unless supplied via `SETUP_TOKEN`. Read it through the local container or volume to approve a pairing using the setup header; do not expose it publicly. Configure the exact hosted dashboard origin in `ALLOWED_ORIGINS`; no wildcard origin is accepted. `fixtureOrigins` is never enabled by environment variables.

SQLite stores the job history, settings and hashed session tokens in the private data directory. S3 keys are stored separately in a file restricted to owner access where supported; they are never included in the settings response. File permissions depend on the host filesystem and OS. Desktop binds loopback; Docker LAN exposure requires deliberate host/network configuration. Supported production source hostnames are Twitch, YouTube, Kick and Chaturbate (including subdomains), using HTTPS. Live checks require yt-dlp's explicit `is_live` status. A capture is remuxed and validated with ffprobe before it is marked complete. An interrupted startup preserves the partial capture and marks it interrupted rather than claiming it completed. Automatic cleanup removes only engine-managed finished recordings; imported media is never removed.

This is beta software. Validate the external tools and supported platform behavior in the target environment before relying on unattended recording. See the migration report for test evidence and outstanding release checks.
