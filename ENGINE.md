# FanSnipe local engine

Requires Node.js 24 or later with `node:sqlite`, plus yt-dlp, ffmpeg, ffprobe and Deno. Install with `npm ci`, run `npm run typecheck`, `npm run lint`, and `npm test`, then `npm start`. Windows additionally requires the source-built `FanSnipe.JobRunner.exe`; recording and tool execution fail closed if it is absent. No media is sent to a hosted FanSnipe service. S3 uploads are initiated explicitly and go directly to the configured endpoint.

`createEngine(options)` from `dist/app.js` returns `{app, server, auth, local, start, stop}`. `start()` resolves to Node's `AddressInfo`; `stop()` quiesces requests and waits for active work. Options: required `dataDir`; optional `recordingsPath`, `dashboardPath`, `host`, `port`, `ytDlpPath`, `ffmpegPath`, `ffprobePath`, `jsRuntimePath` (Deno), `jobRunnerPath` (Windows), `mode` (`desktop` or `docker`), `allowedOrigins` (exact desktop origins), `publicOrigin` (exact Docker reverse-proxy origin), `setupToken`, `lockedFields`, `monitor` (false disables checks), and `fixtureOrigins` (exact allowlist only for testing). The fixture-only test prefix options in the type are not configured by the standalone server. Bundle `dist/supervisor.js` alongside `dist/app.js`.

Native integrations call `auth.listPending()` and `auth.approve(id)` for pairing; `local.setRecordingsPath(absolutePath)` for folder selection; `local.diagnostics()`; and `local.importLegacy(absoluteDatabasePath, approvedMediaRoot)`. Import opens the original database read-only, disables imported channels, and references supported regular media under the explicitly approved root without moving or deleting it. The result reports imported counts, skipped rows and media requiring relinking. An omitted media root imports metadata without linking media. Preserve a backup before migration.

For S3 destination changes, the authenticated browser posts the four destination fields to `/api/v1/settings/s3-approvals`. Native UI polls `local.listUploadApprovals()` and displays the exact destination, then calls `local.resolveUploadApproval(id, approved)`. The requesting session polls `/api/v1/settings/s3-approvals/:id` and uses its one-use approval token in `uploadDestinationApproval` in the subsequent settings PUT. Docker instead approves via authenticated POST `/api/v1/settings/s3-approvals/:id/approve` with `X-Setup-Token`. Tokens are tied to the initiating session and requested destination. Disabling S3 alone does not require approval.

Standalone environment: `DATA_DIR`, `RECORDINGS_PATH`, `DASHBOARD_PATH`, `HOST`, `PORT`, `FANSNIPE_MODE` (with `STREAMSNIPE_MODE` accepted for existing installations), comma-separated `ALLOWED_ORIGINS`, `PUBLIC_ORIGIN`, `SETUP_TOKEN`, `YT_DLP_PATH`, `FFMPEG_PATH`, `FFPROBE_PATH`, `JS_RUNTIME_PATH`, and `JOB_RUNNER_PATH`. Defaults are loopback port 47821 and desktop mode. Without `DATA_DIR`, an existing `~/.streamsnipe/engine.sqlite` is reused in place when `~/.fansnipe/engine.sqlite` does not exist; new catalogs use `~/.fansnipe`. Docker creates a random persistent setup token in `DATA_DIR/setup-token`, mode 0600, unless supplied via `SETUP_TOKEN`; `RECORDINGS_PATH` is locked when supplied. Docker HTTPS reverse proxies must set `PUBLIC_ORIGIN` to the exact external origin and preserve its Host header. Forwarded headers are not trusted. Configure the exact hosted desktop dashboard origin in `ALLOWED_ORIGINS`; wildcards are not accepted.

SQLite stores settings, history and hashed expiring sessions in a private data directory; a separate SQLite lease excludes concurrent catalog owners. S3 keys are stored separately in a file restricted to owner access where supported; they are never included in the settings response. Host OS and filesystem protections still matter. Desktop binds loopback; Docker LAN exposure requires deliberate network configuration. Supported source hostnames are Twitch, YouTube, Kick and Chaturbate over HTTPS. Live checks require yt-dlp's explicit `is_live` status. Captures are remuxed into a staging file, container and streams are verified, then the result is atomically published. Interrupted captures remain available without being marked complete. Automatic cleanup affects only managed finished recordings; imported media and catalog entries are preserved.

On Windows, a user stop terminates the contained recorder job and waits for all job processes to exit. A capture is marked completed only after successful remux and media validation; disk-pressure stops, timeouts and helper failures are marked interrupted. This is beta software. Validate external tools and supported platform behavior in the target environment before unattended recording. See the migration report for evidence and remaining release checks.
